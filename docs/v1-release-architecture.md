# LiftPDF V1 Release Architecture

Date: 2026-08-12

## Application Platform

- Framework: Next.js 15.5.20
- UI: React 19.1.1
- Language: TypeScript
- Hosting: Vercel
- Production domain: `https://liftpdf.com`
- Canonical domain: `https://liftpdf.com`

## Core Engines

| Engine | Responsibility |
|---|---|
| PDF.js | Browser-side PDF loading, page count, thumbnails, text extraction and raster rendering. |
| pdf-lib | Browser-side PDF creation and structural edits: merge, split, rotate, page extraction/deletion/reorder, page numbers and watermark composition. |
| QPDF WASM | Browser-side compression, encryption/protection, unlock/decryption and permission handling. |
| JSZip | Browser-side ZIP creation for multi-file outputs such as split/extract/PDF-to-image. |
| Browser image APIs | Image decoding, dimensions, canvas rendering and JPG/PNG/WEBP to PDF workflows. |

## Client-Side Model

The V1 tool workflows are designed to run in the browser:

1. User selects local files.
2. Browser APIs, PDF.js, pdf-lib, QPDF WASM or JSZip process the files locally.
3. LiftPDF creates object URLs or blobs for download.
4. The user downloads the result.

No V1 tool requires a LiftPDF backend upload endpoint.

## Analytics And Consent

- GA4 is loaded only when `NEXT_PUBLIC_GA_MEASUREMENT_ID` exists and the user accepts analytics.
- Consent defaults to denied.
- Rejected analytics keeps the GA script unloaded.
- Tool events are centralized through `lib/analytics.ts` and `hooks/use-tool-analytics.ts`.
- Payloads are aggregate and do not include filenames, document content, extracted text, passwords or local paths.

## Security Headers

Observed in production:

- `Cross-Origin-Opener-Policy: same-origin`
- `Cross-Origin-Embedder-Policy: credentialless`
- `Strict-Transport-Security: max-age=63072000`
- `X-Powered-By`: not present

No custom CSP is present in V1. This is documented, not changed blindly in the release freeze.

## Routing And SEO Infrastructure

- Static and SSG routes are generated by Next.js.
- `/sitemap.xml` is available and contains HTTPS LiftPDF canonical URLs.
- `/robots.txt` allows crawling and points to `https://liftpdf.com/sitemap.xml`.
- Canonicals use `https://liftpdf.com/...`.
- Tool pages include WebApplication/Breadcrumb/FAQ/HowTo/SoftwareApplication schema where applicable.

## Deployment And Rollback

- Primary deployment path: push to `main`, Vercel production deploy.
- Release tag: `v1.0.0`.
- Rollback options:
  - redeploy the Vercel deployment attached to `v1.0.0`;
  - or checkout/tag `v1.0.0`, rebuild and redeploy.
